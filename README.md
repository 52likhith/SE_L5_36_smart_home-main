# Lab 5: Static Code Analysis - Smart Home Device Controller

## Overview

This project improves the code quality, formatting, and security of a Python-based smart home controller using Pylint, Bandit, and Flake8.

The program registers smart devices, toggles their states, manages thermostat temperatures, lists devices by room, calculates power usage, and saves the current device state to a JSON file.

## Requirements

- Python 3.12 or compatible Python 3 version
- Pylint
- Bandit
- Flake8

Install the analysis tools:

```powershell
python -m pip install pylint bandit flake8
```

## Run the program

```powershell
python smart_home.py
```

The script demonstrates device registration, toggling, thermostat validation, room filtering, power calculations, and state saving. It generates `home_state.json`.

## Run static analysis

Run each tool independently:

```powershell
python -m pylint smart_home.py
python -m bandit -r smart_home.py
python -m flake8 smart_home.py
```

To save the final reports:

```powershell
python -m pylint smart_home.py > pylint_after.txt 2>&1
python -m bandit -r smart_home.py > bandit_after.txt 2>&1
python -m flake8 smart_home.py > flake8_after.txt 2>&1
```

The repository contains before-and-after reports for comparing the original code with the improved implementation.

## Issues addressed

- Replaced the mutable default argument used for device settings.
- Corrected thermostat validation so non-thermostat devices are not modified.
- Added handling for missing device names.
- Changed the hub host from all network interfaces to loopback.
- Replaced hardcoded password assignment with an environment-variable lookup.
- Reworked scene execution to validate script paths and avoid `shell=True`.
- Improved function naming, documentation, file encoding, and formatting.

## Final analysis results

- **Pylint:** 10.00/10.
- **Flake8:** No reported formatting violations.
- **Bandit:** Two Low-severity findings (B404 and B603); zero Medium- or High-severity findings.

The remaining Bandit findings concern use of the `subprocess` module and subprocess execution with `shell=False`. They have not been suppressed.

## Limitations

This is a lab demonstration, not a production-ready smart home service. The environment variable `SMART_HOME_PASSWORD` is read but is not currently used for authentication. The controller uses in-memory device state, and scene execution requires a compatible Bash environment and valid scripts.
